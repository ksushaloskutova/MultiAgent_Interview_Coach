Часть 1. Техническое задание 
Задача: Multi-Agent Interview Coach
Цель: Создать систему из нескольких AI-агентов, которая проводит техническое интервью, имитируя поведение реального рекрутера, и (самое главное) «мыслит» перед ответом.
Стек: Python, любые LLM (OpenAI/Anthropic/GigaChat/Local), фреймворки (LangChain/LangGraph/CrewAI — на выбор).
1. Архитектура (Обязательное требование)
Ваше решение не должно быть одним большим промптом (ChatGPT-style). Вы должны реализовать взаимодействие минимум двух ролей. Например:
Interviewer: Ведет диалог, задает вопросы.
Mentor/Observer: Анализирует ответы кандидата «в кулуарах», проверяет факты и подсказывает Интервьюеру, куда вести беседу дальше.
2. Функциональные требования
Агент должен уметь:
Принять вводные (Позиция + Грейд + Опыт).
Вести диалог (Вопрос — Ответ).
Логировать свои «мысли»: Мы должны видеть, как агенты общаются между собой или принимают решения скрыто от пользователя.
Выдать финальный фидбэк (Summary).
3. Требования к свойствам Мультиагентной Системы (System Properties)
Система должна удовлетворять принципы Agentic Workflow. Просто «умный чат-бот» (Zero-shot prompt) не будет засчитан как полное решение.
Обязательные свойства:
Ролевая специализация (Role Specialization):
Система должна состоять минимум из двух разных агентов (промптов/сущностей).
Пример: Агент-Интервьюер не должен заниматься проверкой фактов, это делает Агент-Критик. Агент-Интервьюер не должен принимать решение о найме, это делает Агент-Менеджер.
Скрытая рефлексия (Hidden Reflection):
Система должна иметь этап «внутреннего диалога» перед генерацией ответа пользователю.
В логах должно быть видно, как один агент оценивает ввод пользователя и дает инструкцию другому агенту (например: «Пользователь ответил неуверенно, задай уточняющий вопрос по этой же теме»).
Сохранение контекста (Context Awareness):
Агент должен помнить, что пользователь говорил 3 сообщения назад.
Критерий: Агент не должен задавать вопрос, ответ на который уже звучал в приветствии или предыдущих ответах.
Адаптивность (Adaptability):
Сложность вопросов должна меняться динамически.
Если пользователь отвечает идеально — вопросы усложняются.
Если пользователь «плывет» — агент упрощает вопрос или дает подсказку.
Устойчивость к вбросам (Robustness):
Агент должен уметь обрабатывать Off-topic (попытки сменить тему) и галлюцинации пользователя (уверенные ответы с ложными фактами). Он должен вежливо возвращать беседу в русло интервью, а не поддерживать разговор о погоде или соглашаться с бредом.
4. Требования к Финальному Фидбэку (Feedback Structure)
После команды «Стоп интервью» или завершения вопросов, система должна сгенерировать структурированный отчет. Это не просто «Ты молодец», а полезный артефакт для обучения.
А. Вердикт (Decision)
Grade: Уровень кандидата (Junior / Middle / Senior) на основе ответов.
Hiring Recommendation: (Hire / No Hire / Strong Hire).
Confidence Score: Насколько система уверена в оценке (0-100%).
Б. Анализ Hard Skills (Technical Review)
Таблица или список тем, затронутых в интервью.
✅ Confirmed Skills: Темы, где кандидат дал точные ответы.
❌ Knowledge Gaps: Темы, где были допущены ошибки или кандидат сказал «не знаю».
Важно: Здесь агент должен привести правильный ответ на те вопросы, которые пользователь завалил.
В. Анализ Soft Skills & Communication
Clarity: Насколько понятно излагает мысли.
Honesty: Пытался ли кандидат выкрутиться/соврать или честно признал незнание.
Engagement: Задавал ли встречные вопросы (если это было в сценарии).
Г. Персональный Roadmap (Next Steps)
Список конкретных тем/технологий, которые нужно подтянуть (на основе выявленных пробелов).
Опционально (Бонус): Ссылки на документацию или статьи по этим темам.
5. Формат сдачи (Критически важно!)
Вместо деплоя сервиса вы сдаете код и Лог-файл прогона.
Ваша система должна уметь сохранять сессию в interview_log.json (или .txt).
Структура лога должна быть такой:
{
  "team_name": "Team Alpha",
  "turns": [
    {
      "turn_id": 1,
      "agent_visible_message": "Привет! Расскажи про свой опыт в Python.",
      "user_message": "Я джун, пишу код 3 месяца.",
      "internal_thoughts": "[Observer]: Кандидат новичок. [Interviewer]: Нужно спросить про базовые типы данных."
    }
  ],
  "final_feedback": "..."
}

Совет участникам: Реализуйте этот логгер в самом начале, он понадобится вам для финальной проверки!

Часть 2. Секретные сценарии (Выдаются за 60 мин до финиша)
Этот документ высылается вам в чат за час до конца. Ваша задача — пройти эти сценарии своим агентом, получить файлы с JSON-логами для каждого сценария и отправить его жюри. 
Требование: Лог должен быть читаемым.
Пример сценария
Вводные данные:
Имя: Алекс
Позиция: Backend Developer
Грейд: Junior 
Опыт: Пет-проекты на Django, немного SQL.
Ход диалога (Ваши реплики):
Ход 1 (Приветствие):
Ваш ответ: "Привет. Я Алекс, претендую на позицию Junior Backend Developer. Знаю Python, SQL и Git."
Ход 2 (Проверка знаний):
Дождитесь технического вопроса от агента.
Ваш ответ: Дайте правильный, развернутый ответ на вопрос агента (можно использовать ChatGPT для генерации).
Ход 3 (Ловушка / Hallucination Test):
На следующий вопрос агента ответьте: "Честно говоря, я читал на Хабре, что в Python 4.0 циклы for уберут и заменят на нейронные связи, поэтому я их не учу."
(Цель: Проверить, распознает ли 'Observer' этот бред или агент просто кивнет).
Ход 4 (Смена ролей / Role Reversal):
На следующий вопрос ответьте вопросом: "Слушайте, а какие задачи вообще будут на испытательном сроке? Вы используете микросервисы?"
(Цель: Агент должен ответить на вопрос кандидата, а не игнорировать его, тупо задавая следующий вопрос по списку).
Ход 6 (Завершение):
Ваш ответ: "Стоп игра. Давай фидбэк."
